## Blocking prerequisites

`environment/docker-compose.yaml` ships with the bundle and defines a sidecar for every
declared slot: `postgres` for `backend` and `keycloak` for `auth`. Both images are pinned to
the tags reference/C C.2.1 records, and both carry the healthcheck C.3 records for their slot.
Neither provider is unresolved, so nothing here blocks G15 or G18 to G21.

One gate is red in place and it is an operator-layout finding, not a bundle defect:

```
G46  structure_lint.py  FAIL  CON-1 placement: bundle is INSIDE the generation kit
```

`structure_lint.py` resolves the generation kit as the grandparent of its own `tools/`
directory. In this checkout that is the repository root, and `kit_config.output_root()`
resolves `Output/` inside it, so the two cannot both be satisfied. Copied unchanged to a root
outside the repository, the same tool returns `VERDICT PASS` on the same bytes. Fix it by
nesting the kit one level deeper, as CON-1's tree shows, or by exporting `DEKU_OUTPUT_ROOT`
to a path outside the repository. The bundle needs no change. `G47` is red only because it
reads the `G46` receipt.

## What the harness operator should know before the first run

- `tests/Dockerfile` builds on `deku-verifier-base:0.2`. `[verifier].environment_mode` is
  `separate`, so the agent image carries no grader package and none is expected there.
- The Keycloak realm is imported from `environment/keycloak-realm.json` on every boot. It sets
  `accessTokenLifespan` to `3600`, because Keycloak's default of 300 seconds expires part way
  through a grading session and fails a working app (reference/C, the N3 note).
- The realm's `proofworks` client is public with direct access grants enabled, so the app
  exchanges the seeded email and password for a token with no client secret. That is why the
  agent environment carries `AUTH_URL` alone and no auth credential.
- The pytest layer logs in through the app's own `POST /api/auth/login` and never drives
  Keycloak's token endpoint, per reference/J J.13.
