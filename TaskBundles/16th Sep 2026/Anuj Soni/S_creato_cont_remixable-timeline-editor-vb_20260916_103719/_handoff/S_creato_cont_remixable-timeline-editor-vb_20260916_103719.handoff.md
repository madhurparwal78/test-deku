## What the operator should read first

`_handoff/S_creato_cont_remixable-timeline-editor-vb_20260916_103719.report.md` carries the gate log, the slot obligations, the rubric budget and the
literals ledger. Three decisions in it are worth knowing before the app is built:

1. **The last unit of a limit is the task.** Each plan stores seven limits, three monthly
   allowances and four ceilings, and the server enforces them. When two requests claim the last
   unit at once, exactly one succeeds. A retried export with the same `request_key` costs one
   unit, not two. Three workflows push the seat, saved-block, brand-kit and variation limits
   concurrently, and a fourth pushes two saves from one revision.
2. **Exports are rendered in the browser and validated on the server.** The server checks the
   magic bytes and header dimensions against the plan's ceiling. It stores the file privately
   under the workspace's prefix and serves it only through app routes, never through a presigned
   address. When a share link's download switch is off, the download route itself must refuse
   the file; hiding the control is not enough.
3. **The reviewer is a separate account role, created only from a review invitation.** A
   reviewer sees only the versions whose approval was requested of them, can comment at a
   timecode, and records one decision per request. The server refuses them on every workspace,
   project and member-only endpoint. An app that only hides those links in the interface fails
   the authorization workflow.
