## What the operator should read first

1. `instruction.md` is the only file the agent sees. Everything else here is held out.
2. `solution/checklist.md` is the coverage target the reference app is built from.
   324 items, every one cited by a grader, proven in both directions by
   `coverage_map.py` (G24).
3. `tests/traceability-matrix.md` maps each core ask to the checks that grade it. It
   is regenerated by every sweep, so it cannot disagree with the gate.
4. `_handoff/<code>.report.md` carries the full gate log, the literals ledger summary
   and the grading-window measurement.

## The two things most likely to go wrong downstream

**The draft gate.** A record that is not published must be absent from every public
endpoint and must answer not found on its own route, and the only thing that opens it
is a token the server verifies against a stored hash. A reference app that filters the
unpublished records in the page, or that reads the token in the browser and then asks
for drafts with a shared credential, will look correct in a browser and fail
`test_draft_record_is_absent_from_every_public_endpoint`,
`test_preview_token_is_verified_on_the_server` and `test_preview_token_is_stored_as_a_hash`.

**The media pipeline.** Every master and every rendition must be a real object in the
bucket at `media/<content-hash>/<variant>.<ext>`, and a media may reach `ready` only
once its objects exist. A build that writes renditions to the app container's
filesystem, or that marks a record ready before the objects land, passes its own
reading of the brief and fails `test_rendition_bytes_live_in_the_bucket_and_nowhere_else`
and `test_rendition_key_follows_the_content_addressed_shape`. The gated seeded record
exists precisely to prove the publish gate reads that state: it references a media that
is still deriving and can never reach the live state.
