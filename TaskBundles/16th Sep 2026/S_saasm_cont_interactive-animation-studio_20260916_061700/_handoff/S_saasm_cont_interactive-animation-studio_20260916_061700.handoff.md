## Where this bundle sits, and why two gates are red

This bundle was placed at `GreenField-GenKit2/Output/` on request. That directory is
INSIDE the generation kit, and CON-1 forbids it:

```
CON-1 placement: bundle is INSIDE the generation kit
  ('/Users/apple/Downloads/GreenField-GenKit2')
```

`structure_lint.py` resolves the generation kit as `tools/../..`, which is the whole
repository, not the `deku-green-field/` package inside it. `kit_config.output_root()`
agrees: with `output_root: FILL` it returns the repository's PARENT plus `Output`.
So every path under `GreenField-GenKit2/` fails, and this one cannot be configured
green -- `output_root` moves the FIRST CON-1 check, but the inside-the-kit check
takes no configuration at all.

**The risk CON-1 is naming is real here.** `Output/` is untracked and NOT in
`.gitignore`, so a `git add -A` in this repository commits generated bundles into the
kit, and a clean checkout or a `git clean -fdx` deletes them. That is the
divergent-corpus defect the rule exists to prevent, and it is one command away in
either direction.

**The remedy is one move**, after which the sweep is green with no other change:

```bash
mv /Users/apple/Downloads/GreenField-GenKit2/Output/16sept-rive \
   /Users/apple/Downloads/Output/16sept-rive
```

**The content is proven independently.** The same bytes swept at a compliant path
returned ALL GATES GREEN across all 32 receipts, and that evidence ships beside this
contract as `../<code>.gates-compliant-path.jsonl`. The two files differ in the G46
and G47 rows and nowhere else; every `inputs` hash is identical, because the bundle
is identical.

## The verifier URL under separate mode -- a question for the operator

`[verifier].env` keeps `APP_PUBLIC_URL = "${APP_PUBLIC_URL:-http://localhost:4173}"`,
which is what `qc_toml.md` VERIF-005 pins and what the kit's own template emits. Under
`environment_mode = "separate"` the grader runs in its own container, where `localhost`
is the grader rather than the app, so read literally that default points at nothing.
The kit cannot settle it: the commit that made `separate` the default records that no
vendored grader file reads `environment_mode` at all, so where the grader resolves the
app is a Harbor orchestration fact. Harbor is expected to inject `APP_PUBLIC_URL`, in
which case the default never applies. **If it does not, this is the line to change**,
to `http://main:4173`, matching the agent side. Stated rather than patched, because
patching it would put the bundle out of step with the pin every other bundle follows.

## Re-running the sweep

The sweep is not self-contained: **G51 needs the companion document and its waiver
list, and only the document falls back.** Run it exactly this way, or G51 reports
NOT-APPLICABLE and `output_qc.py --final` turns that into a red G47 -- a bundle that
reads unfinished for want of two flags rather than for want of anything real.

```bash
KIT=<kit>/deku-green-field
B=Output/16sept-rive/S_saasm_cont_interactive-animation-studio_20260916_061700
CODE=$(basename "$B")

# One --waive per line. Read into an array: most waived headings contain
# spaces, so an unquoted $VAR here splits them into nonsense flags and the
# gate waives topics nobody named.
WAIVE=()
while IFS= read -r line; do
  [ -n "$line" ] && WAIVE+=(--waive "$line")
done < "$(dirname "$B")/$CODE.g51-waivers.txt"

python3 "$KIT/tools/revalidate.py" "$B" "${WAIVE[@]}"
python3 "$KIT/tools/output_qc.py"  "$B" --final
```

`--source` is omitted on purpose: `_handoff/<code>.sources.json` records the
companion (`/Users/apple/Downloads/rive_prd.md`) and `revalidate.py` falls back to
it, so the provenance is something this bundle states about itself rather than
something living in one person's shell history. If that path has moved, edit the
JSON rather than passing a flag. The 145 waived headings have no such fallback and
must be passed every time; each one is a source subject deliberately out of scope
for this task, and the receipt records them so a waiver is a decision on the record
and not a silence.
